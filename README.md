# Omarchy

Omarchy is a beautiful, fun & agentic Linux distribution by DHH.

Read more at [omarchy.org](https://omarchy.org).

## Onsen edition

This fork is Omarchy Quattro with the changes below written into the files it ships. Hypr loads `default/hypr/` from this tree, then the `~/.config/hypr/` overrides, which stay as Quattro ships them apart from the monitor scale, mode, and placement direction. The other config under `config/` ships through `/etc/skel` and is copied onto the home.

Each item below is one commit on top of Quattro, in order.

**Keeping a machine on it: `onsen update`.** `onsen` is this fork's own command, a Go program (`cmd/onsen`, its parts under `internal/`). Install it from the checkout with `go install ./cmd/onsen`; it lands in `~/go/bin`, which the session PATH carries. From then on `onsen update` keeps it current: when a rebase changes its source, it builds itself, checks that the build starts, installs it, and finishes the run as the new build (a build that fails leaves the installed one in place, and the run carries on and reports it). `onsen` alone will show the machine's status (for now it prints where to go instead). `onsen update --check` runs only the drift check below and reports the fork's state, changing nothing. `onsen diff` shows, as diffs, every shipped file whose live copy differs from the edition's, the files on `default/onsen/drift-ignore` included, and names the local files below an ignored path: the drift the check does not stop on, which an app rewrote and a rebuild would lose, so a change worth keeping can be carried into the fork by hand (`--ignored` for those alone, `--names` without the diffs). `onsen update` brings the machine fully up to date. It stops first if any config in `~/.config`, `~/.gnupg`, or `~/.ssh` that the edition ships has been edited by hand (an edit that matches the checkout's copy is a change committed and not yet shipped, so committing drift clears it), or has a new file beside it in a directory the edition ships into (`default/onsen/drift-ignore` lists the paths apps write themselves), or sits below a directory that is a link (it never writes through one), or if a package is explicitly installed that neither Quattro's install lists nor `default/onsen/packages` declares (stock `omarchy` and `omarchy-settings` are allowed: the same run replaces them). It then rebases these commits onto upstream Quattro (they are pushed, so jj would call them immutable; the rebase overrides that) and stops on a conflict. It pulls upstream's PKGBUILDs and shows, as patches, what changed under `pkgbuilds/omarchy-nvim` since the last run: the Neovim config this edition carries a copy of in `config/nvim`, so an idea there is copied over by hand or left, never merged. It builds `omarchy-dev` and `omarchy-settings-dev` from this tree with upstream's PKGBUILDs (`~/src/kingland.io/omarchy-pkgs`), signs them with the YubiKey, and publishes them to the local `[onsen]` repository at `/var/lib/omarchy-onsen`. `[onsen]` is kept the first repository, since `[omarchy]` carries packages with the same names. It removes the packages the edition takes away, runs the stock `omarchy update` unattended, installs the declared packages that are missing (repository ones with pacman, `aur:` ones with yay; a `local:` one is built by hand from its own checkout, so it is only named when missing), keeps the machine's identity files in step with their copies under `~/state/identity` (the tailnet node key, the SSH host keys, the Syncthing device, the Bluetooth pairings, the touch-to-sudo enrolment: live wins, the copy is refreshed from it, and on a fresh install a copy fills what is missing, so a rebuilt machine comes back as itself; `onsen identity` shows the two side by side), copies the config files the new `/etc/skel` ships into `~/.config`, `~/.gnupg`, and `~/.ssh`, removing any it stopped shipping that are unchanged, and then enables the services `default/onsen/services` declares, after the copy so a unit the config ships is in place first (one already enabled but not running is started: a user unit whose start condition failed at login stays dead until then). A file it replaces that matched neither the last run nor the edition (on a machine's first run, any file it replaces) is kept under `~/.local/state/omarchy/onsen-replaced/`. A declared package that will not install or a service that will not start does not stop the run: it finishes, names the problem, and exits non-zero. Ctrl-C lets the running program finish its own cleanup and stops before the next. Only one update runs at a time. sudo is asked for once, up front, and kept fresh for the whole run, so a prompt never lands mid-step and times out; once the wheel rule is in, it never asks. A reboot the update needs is offered last. It never runs `omarchy-reinstall-configs`, because `/etc/skel` also marks every migration done. To bring a fresh install of stock Quattro onto the edition: install `pcsclite`, `ccid`, `jujutsu`, and `go`; enable `pcscd.socket`; copy `bin/omarchy-hw-platform` from the checkout into `~/.local/bin` (stock 4.0.4 ships none, and the channel switch asks it for the platform before the fork's package provides it); build and enable smartsocket from its own repo (`make install enable`), which provides `pinentry-smart`; import the signing key's public half (`curl -s https://github.com/lkingland.gpg | gpg --import`; the card has no key URL); clone this repo colocated as `~/src/kingland.io/onsen` (`jj git clone --colocate`, then add the `upstream` remote) and upstream's `omarchy-pkgs` beside it; then, in the checkout, `go install ./cmd/onsen` and run `~/go/bin/onsen update` (the PATH line that finds `~/go/bin` ships with that first run and takes effect at the next login). A machine being rebuilt first copies its `~/state` (and the other home folders) back from cumulus, so that `onsen update` restores its identity before it enables tailscale and Syncthing; a new machine has nothing to restore, and that run captures its identity. Accept the reboot it offers and run it once more; the second run should find no drift.

- **System.** oomd: Masked, because the agent fleet lives in `app.slice` and one oomd kill there ends every pane. Migration `1791858700`. Sudo: wheel needs no password for sudo, and sudo keeps `SSH_AUTH_SOCK`. File: `etc/sudoers.d/50-onsen-agent-sudo`. Migration `1791858701` retires the hand-made `ssh-nopasswd` once this file is in place. DNS: Cloudflare over TLS (opportunistic), Quad9 as the fallback. File: `etc/systemd/resolved.conf.d/50-onsen-dns.conf`. Podman and Sunshine: The rootless Podman API socket and Sunshine run as user services, declared in `default/onsen/services`. Sunshine's streaming ports open on `tailscale0` only, like SSH; its credentials live in `~/state`. Migration `1791864400`. Ollama: The hamr-memory embedder runs on the CPU: `etc/systemd/system/ollama.service.d/cpu-embedder.conf` hides the GPU from the unit, because on ROCm the loaded model holds the card at 100% and about 90 W while idle. `ollama.service` is a declared service. Bluetooth input: trusted, paired keyboards and trackpads are paged at login and for the rest of the session by `omarchy-bluetooth-reconnect`, a user unit in `config/systemd/user` enabled as a declared service, since bluez retries only audio profiles; the controller is also made connectable as it appears (`etc/udev/rules.d/70-onsen-bluetooth-connectable.rules`), because bluez leaves page scan off and a trackpad that wakes on a touch then cannot call in, which is why it seemed never to; audio devices are left alone; enhanced retransmission is off (`etc/modprobe.d/bluetooth.conf`) because the Magic Trackpad drops its HID node with it on. Agent and dictation: `config/omarchy/defaults/agent` is claude and `defaults/dictation` is voxtype (stock ships superwhisper), the files Omarchy's setup writes, so a fresh install starts with both set.
- **Keys.** Config reset: `omarchy-reinstall-configs` replays a copy of `/etc/skel` with `~/.ssh` and `~/.gnupg` removed. Those trees are `onsen update`'s to keep, with a record of what it wrote; the replay has none and would clobber. YubiKey: SSH: `~/.ssh/config` ships from `etc/skel/.ssh/config`, and `onsen update` keeps it current as it does `~/.config`. GitHub and gitea pin `IdentityAgent` to smartsocket's socket at the standard gpg-agent path, so a session that arrived with a forwarded agent still offers the card key and not the first key of the agent it brought. `Host *` is last, so the tighter stratus keepalives win. `~/.ssh/config.d/*.conf` is included first and never managed. GnuPG: `pinentry-smart` forwards the PIN to nimbus when that socket is up, and otherwise uses `PINENTRY_SMART_FALLBACK` (`/usr/bin/pinentry`, Arch's chooser, which picks the themed `pinentry-gnome3` on this desktop; set by the gpg-agent-local drop-in `config/systemd/user/gpg-agent-local.service.d/10-pinentry-fallback.conf`, which ships with `~/.config`). scdaemon uses pcscd and disables PIV so the PIN stays cached; the PIN cache is a day. The confs ship in `/etc/skel/.gnupg`, and `onsen update` manages `~/.gnupg` and `~/.ssh` exactly as it manages `~/.config`. The wheel rule for pcscd is package-owned at `etc/polkit-1/rules.d/99-pcscd-wheel.rules`. `pcsclite` and `ccid` are declared packages and `pcscd.socket` a declared service; smartsocket (`pinentry-smart`) is built from its own repo. Git and Jujutsu: Both sign with OpenPGP subkey `7DB461E762F282F9` on the YubiKey, under the same name and email. Git's `defaultBranch` is `main`. Jujutsu keeps git-style diffs through delta, and runs difftastic as `jj ds` and `jj dd`. Files: `config/git/config`, `config/jj/config.toml`. SSH in: Keys only, no root, and only over the tailnet. `etc/ssh/sshd_config.d/50-onsen.conf` turns off passwords and keeps `StreamLocalBindUnlink yes`, so Nimbus can forward its gpg-agent socket again after a dropped session. Migration `1791830300` enables sshd and lets 22/tcp and mosh (60000-61000/udp, declared in `default/onsen/packages`) in on `tailscale0` only; stock `omarchy-setup-security-sshd` would open 22 on every interface.
- **Hyprland.** Keys, input, and gestures sit in the user override files stock provides, `config/hypr/bindings.lua` and `input.lua`, so `default/hypr` stays upstream's. Super + number goes to that number's workspace on the focused monitor (Hyprland's `r~N` selector), not to a global id, and Super + Ctrl + number focuses monitor N (stock opens the bar's Nth panel; the letter binds for the panels stay). HJKL focuses and Shift+HJKL moves the window. Togglesplit is Ctrl+J and the keybindings menu is Shift+Ctrl+K. Q is the previous workspace, E the next, and W still closes. The workspace-layout cycle, including its floating mode, has no key: L is focus-right. Ctrl+K stays Herdr and Ctrl+L the lock. Compose is Right Alt and key repeat is 40/200. The trackpad uses natural scroll, two-finger click, scroll factor 0.4, drag-lock in libinput's timeout mode, and tap-and-drag. Outer gap is 0. One visible tiled window, and a workspace that is a single group, draws no border. A trackpad swipe keeps going past the end workspaces. The desk is a 42" 4K at scale 1.25, and GDK scale stays 2. Files: `default/hypr/bindings/tiling.lua`, `default/hypr/bindings/utilities.lua`, `default/hypr/input.lua`, `default/hypr/looknfeel.lua`, `config/hypr/monitors.lua`. Bar: Sits on the bottom edge and overlays, so it never reserves a strip and showing or hiding it never moves tiled windows. Its workspaces widget (`shell/plugins/bar/widgets/Workspaces.qml`, the fork's second patch to an upstream file) shows each bar its own monitor's workspaces, numbered by position as Super + number reaches them, not every workspace by global id. It starts hidden (`bar-off`, created once by migration `1791797200`), and resting the pointer on the bottom edge brings it back until the pointer leaves it: a compositor timer in `config/hypr/looknfeel.lua` polls the pointer, since Hyprland raises no event for pointer motion; a bar shown by hand is left alone. Its edge, overlay, and background are applied once by migration `1792042330`: the edition ships `config/omarchy/shell.json`, but Omarchy's first login writes one before the edition's copy can seed it. Super+Shift+Space shows or hides it, and upstream keeps that choice across login. When it is shown it may cover tmux. Files: `config/omarchy/shell.json`, `shell/plugins/bar/Bar.qml` (the `overlay` property). JetKVM: the KVM's screen on the second DisplayPort output is a 1080p monitor at scale 1, placed to the left like any later output and matched by description (`config/hypr/monitors.lua`); its absolute pointer is narrowed to that screen's share of the layout by a libinput calibration matrix (`etc/udev/rules.d/71-onsen-jetkvm-pointer.rules`), since Hyprland binds only tablets and touchscreens to an output; on its keyboard left Alt is Super (`config/hypr/input.lua`), because a Mac client keeps Command for itself. Look: a 5 px outer gap (`config/hypr/looknfeel.lua`), because the LG TVs' edges do not land exactly on the panel's and a flush window loses its border there; a lone window keeps its border, since on two desks the active border is what says which monitor has focus; the inner gap is stock.
- **Branding.** The screensaver banner spells the machine's owner, not Omarchy. It is `logo.txt`: the settings package installs that over `/etc/skel/.config/omarchy/branding/screensaver.txt` after it copies `config/`, so the copy under `config/omarchy/branding/` is the same text, kept for the drift check, which reads the checkout's `config/`.
- **Web apps.** SoundCloud has no desktop client, so it is a web app like stock's X and YouTube: `applications/SoundCloud.desktop` opens it in the browser's app mode (its own window and icon; playback reaches the media widget and keys over MPRIS), with the icon under `applications/icons/`, which the settings package installs into the hicolor theme.
- **Tmux.** Quattro's prefix, splits, history, and truecolor stay. Added: OSC 8 hyperlinks, the Onsen two-line status bar on the bottom, stable window names, session jumps on `f` / `F` / `s`, `prefix+l` back to the last session, `prefix+Tab` next window (`prefix+Shift+Tab` previous), Shift+Enter delivered as Alt+Enter so Grok can take a newline, `prefix+C-k` kills the session, `prefix+a` to a blocked agent, vim `HJKL` pane swap, and saving window order on move. Files: `config/tmux/tmux.conf`, `sessions-menu`, `sessions-ordered`. `session-order.example` is the pin-list template. The live `session-order` stays on the machine. TPM, tmux-sensible, and vim-tmux-navigator are named in the config; migration `1791972926` clones TPM and installs them once, and the navigator takes `C-l`.
- **Terminals.** Foot: Shift+Return sends Alt+Return (ESC CR), which tmux hands to Grok as a newline. File: `config/foot/foot.ini`.
- **Env.** `~/.local/bin` and `~/go/bin` are on the PATH for the whole session: `config/uwsm/default` for the session itself (uwsm exports the environment it computes over environment.d's), `config/environment.d/path.conf` for the user services that start before it. `CLAUDE_CONFIG_DIR` points Claude Code at `~/state/claude`, so its config and `.claude.json` live with the other runtime data. Files: `config/environment.d/path.conf`, `config/environment.d/claude.conf`.
- **Shell.** Bash, as stock. The edition's config is `config/bash/rc`, sourced from `~/.bashrc` (migration `1791972923` adds the line once; the shipped `.bashrc` stays stock), and `~/.config/bash/rc.d/*` is sourced last so a theme can add its colors. It carries the aliases and functions (git, eza, systemd, the clipboard, media, a directory stack on `c` and `o`, and `poweroff`, `reboot`, and `shutdown` that ask for the hostname first), atuin as the history through `bash-preexec`, and the Bitwarden, Jira, and Linode wrappers in `config/bash/tools`; none holds a secret, tokens are read from Bitwarden when a command runs. `c`, `cx`, `h`, `ga`, and `gd` replace Omarchy's. `config/atuin` is atuin's settings; its history lives in `~/state`.
- **Neovim.** `config/nvim` is Omarchy's Neovim config, the LazyVim starter plus the overlay in `omarchy-pkgs/pkgbuilds/omarchy-nvim`, byte for byte, with the operator's setup added beside it, so an upstream change there is a copy here and not a merge. The additions are the plugin specs under `lua/plugins`, `plugin/after/onsen-options.lua` and `onsen-keymaps.lua` (Neovim runs `plugin/` after `init.lua`; the keymaps wait for VeryLazy so they land after LazyVim's), and the Go extra in `lazyvim.json`. The clipboard is Omarchy's `remote_clipboard`; format on save is on, as LazyVim ships it. The Onsen colorscheme, the lualine pills, and the markdown heading colours ride the palette commit. It ships through `/etc/skel` like the rest, so a hand edit stops `onsen update` until it is in the fork. `lazy-lock.json` is managed: a plugin update shows as drift, and committing it pins the versions. `lua/plugins/theme.lua` links to the current Omarchy theme's `neovim.lua`, as the stock starter does. Stock `omarchy-nvim` owns the same paths, so `default/onsen/packages` removes it (and declares `neovim`, which it brought), and `onsen update` first deletes any starter file left unchanged in `~/.config/nvim` that the edition does not ship. `EDITOR` stays Quattro's launcher, which opens nvim.
- **Font.** GoMono Nerd Font, in the terminals, the kitty default, the foot screensaver, and the monospace fontconfig alias. The package is `ttf-go-nerd`.
- **Onsen palette.** Black background, foreground #E0E0E0, pastel green #8FD9A8, pastel blue #A8C4F7, shipped as the `onsen` theme with btop and neovim variants (`themes/onsen/`). Starship uses it in a two-line prompt; a jj repo shows the bookmark and short change id, and the prompt passes `--ignore-working-copy` so it does not snapshot or sign. The character module is off, because nushell draws the vi-mode mark. Command duration, the kubernetes context, and the language and cloud modules stay. Hunk, bat, and the jj log use it too; bat adds numbers and a grid, and `install/user/bat.sh` runs `bat cache --build` once the theme is on the home. Files: `config/starship.toml`, `config/hunk/config.toml`, `config/bat/config`, `config/bat/themes/onsen.tmTheme`, the `[colors]` table in `config/jj/config.toml`. The shell colours are `config/bash/rc.d/colors` (ls and eza, bat, eza's theme directory) and `config/nushell/autoload/onsen-colors.nu`; Neovim's are `config/nvim/colors/onsen.lua`, `lua/onsen`, and the lualine pills in `lua/plugins/lualine.lua`.
